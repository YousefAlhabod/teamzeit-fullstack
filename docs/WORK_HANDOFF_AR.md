# تعليمات الإعداد الأصلية – محفوظة كمرجع

تم تنفيذ النشر والإعداد. الحالة النهائية والاختبارات موثقة في `RELEASE_STATUS.md`. لا تعِد إنشاء قاعدة الإنتاج أو حساب التهيئة اعتمادًا على القائمة التاريخية أدناه.

## الهدف
نشر مشروع TeamZeit الموجود في هذا المجلد بوصفه مشروع Full-Stack مستقلًا على النطاق الفرعي `teamzeit.yousef-alhabod.de`، وإضافة رابط واضح إليه في الموقع الشخصي الرئيسي `yousef-alhabod.de`، من دون حذف أو إتلاف أي جزء من الموقع الحالي.

## التعليمات
1. افحص المستودع والملفات واختبارات Node. شغّل `npm run check` وتحقق من عدم وجود أسرار في المستودع.
2. استخدم الحسابات التي أربطها بنفسي من خلال المتصفح (GitHub وCloudflare). لا تطلب كلمات المرور أو مفاتيح API في المحادثة.
3. أنشئ مستودع GitHub جديدًا مستقلًا للنسخة التقنية. حافظ على الأدوار الأصلية: Vanessa = Product Owner، Ünal = Scrum Master، Stefan = Developer US01، Suzana = Developer US02، Yousef = Developer US03؛ مع اعتماد Yousef بوضوح كمنفذ Full-Stack **لهذه النسخة التقنية**.
4. أنشئ Cloudflare D1، حدّث `wrangler.jsonc` بمعرف قاعدة البيانات الصحيح، طبّق migrations، وضع `SETUP_TOKEN` عبر إعدادات Secrets لا داخل GitHub.
5. انشر Worker وStatic Assets، واختبر: حالة API، التهيئة، تسجيل الدخول، إصدار الدعوات، التسجيل كعضو، إضافة/تعديل موعد، Zu-/Absage/Vielleicht، إظهار Teilnehmerliste للمدرب فقط، وتسجيل الخروج.
6. اربط النطاق الفرعي `teamzeit.yousef-alhabod.de` واختبر شهادة HTTPS. أضف في الموقع الأصلي رابط Portfolio إلى التطبيق بعد التأكد من عمله.
7. لا تصف Demo بأنها تطبيق إنتاجي مستخدم من نادي حقيقي. لا تنشر أسماء زملاء المجموعة على الموقع دون التأكد من موافقتهم، ولا تُفعّل دخول مستخدمين حقيقيين قبل اكتمال بيان الخصوصية ومتطلبات حماية البيانات.
8. لا تدّع إكمال الميزات التي لم تُنفذ (إشعارات Push والبريد التلقائي والصور والإحصاءات). إن طُلب توسعها، قدمها على فروع منفصلة مع اختبار.
9. أرسل رابط الموقع المباشر والرابط إلى GitHub وملخصًا بنتائج الاختبار عند اكتمال النشر.

## رابط العرض
قبل النشر، صفحة HTML تعرض تجربة Demo تفاعلية في المتصفح بدون بيانات شخصية، وتطبيق Live حقيقي عند وصل Worker بقاعدة D1.
